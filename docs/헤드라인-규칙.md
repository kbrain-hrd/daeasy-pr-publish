# 헤드라인 생성 규칙

## 핵심 원칙

헤드라인 생성은 서로 다른 두 작업의 연속이다.

> **① 본문에서 구체적인 사실을 찾는다. ② 그 사실을 본문을 읽지 않은 사람도
> 즉시 이해할 수 있는 독자 언어로 번역한다.**

①만 하고 ②를 건너뛰면 내부 용어 압축("AI 합계를 검산 규칙대로")이 되고,
②만 의식하면 어느 교육에나 붙는 일반론("AI 역량 강화")으로 후퇴한다.

**최종 제목은 항상 "구체적이면서 이해 가능"을 동시에 만족해야 한다.**

억지로 새로운 의미를 만들거나 검색어를 삽입하지 않는다. 순서는 언제나
**구체적인 사실 → 독자 언어로 번역된 의미 → 자연스러운 기사형 헤드라인**이다.

---

## 1. 품질 우선순위 — 위가 아래를 이긴다

세부 규칙이 상위 기준(특히 P1·P4)을 훼손해서는 안 된다.

### P1. 독자 이해 가능성 (최우선)

제목만 읽은 사람이 본문 없이도 무슨 일이 있었는지, 무엇이 특이한지 이해할 수 있어야 한다.
본문에서만 통하는 내부 용어·축약어·업무 맥락·교육 과정 내부 명칭을 제목에 압축하지 않는다.

나쁜 방향: `AI 합계를 검산 규칙대로 다시 확인했습니다` — "AI 합계"·"검산 규칙"이 무엇인지 알 수 없다.
좋은 방향: `AI가 계산한 합계의 오류를 직접 찾아냈습니다` — 상황이 그려진다.
(특정 예시 문장의 복제가 아니라 **내부 사실을 이해 가능한 의미로 변환**하는 것이 핵심이다)

### P2. 본문 고유성

해당 홍보글에서 실제로 확인되는 구체적 사실·장면이 제목에 있어야 한다.
`AI로 달라진 업무 방식`·`생성형 AI로 업무 혁신`·`AI 활용 역량을 높였습니다`처럼
다른 교육 후기에도 그대로 붙는 표현만으로 제목을 구성하지 않는다.

### P3. 구체적인 사실

본문에 실제로 존재하는 작업·오류·결과·산출물·사용 사례·업무 변화·실습 장면·
발견된 문제·해결 과정 중 하나를 중심 소재로 삼는다.
단, **본문의 내부 표현을 그대로 복사하는 것이 목적이 아니다.**

**구체적 ≠ 내부 용어 사용.** `검산 규칙`이라는 단어를 넣는 것보다
`AI가 계산한 합계의 오류를 직접 찾아냈습니다`처럼 **그 규칙이 실제로 무엇을 했는지
설명하는 쪽**이 더 구체적일 수 있다.

### P4. 자연스러운 한국어

사실을 억지로 압축해 명사구를 이어 붙이지 않는다 (`A 합계`·`B 규칙`·`C 절차`·`D 기반`·
`E 적용`·`F 검증` 류). 어색한 의인화·비관용 연어를 만들지 않는다.
**소리 내 읽었을 때 사람이 실제로 말할 법한 문장**이어야 한다. 대구·숫자 반복 같은
말맛을 노리지 않는다 — 평이한 문장이 기본값이다.

### P5. 검색 주제 적합성

기관명·과정명·핵심 주제와 자연스럽게 연결되면 충분하다.
검색어는 주제 적합성의 판단 재료이지 삽입 목록이 아니다 — **제목 품질을 희생하면서
강제 삽입하지 않는다.**

### P6. 예시·기존 제목과의 독립

REFERENCE EXAMPLE(4절)의 품질 특성은 학습하되 문장 골격·수사법·대비 구조·표현·
주요 어구·문장 패턴을 재사용하지 않는다. 기존 게시물 제목도 구조적으로 모방하지 않는다.
검사 대상은 단어가 아니라 **문장 구조와 수사 패턴**이다 — 공통된 일반 명사는 무관하다.

### P7. 형식·세부 (위 기준 충족 후 검수)

- 구조: **`<기관·과정명> — <헤드라인 메시지>`** — 앞부분은 목록 식별자, 차별성은 줄표 뒤에서.
- 60자 이하. 핵심 메시지는 **하나만** (여러 사실의 병렬 나열 금지).
- `기관 + 교육명 + 인원 + 인증`처럼 수치·결과를 늘어놓은 성적표형 금지
  (기관·과정 라벨 자체는 관례라 허용).
- 클릭베이트·과장 금지. 본문에 없는 의미를 보태지 않는다.
- 양식의 **희망 헤드라인**이 5절 3-CHECK를 통과하면 메시지로 우선 채택한다(그대로 또는 다듬어서).

## 2. 생성 절차 — 의미 번역을 건너뛰지 않는다

### STEP A. 본문 사실 추출

본문에서 실제 사실을 사건의 흐름으로 추출한다. 본문에 없는 사실은 추가하지 않는다.

```
AI가 사업실적 합계를 계산함 → 결과에 오류가 발생함 → 사람이 결과를 검토함
→ 오류를 발견함 → 결과를 확인하는 절차를 만듦 → 발표 전에 오류를 걸러냄
```

### STEP B. 내부 표현 ↔ 독자 표현 분리 (의미 번역)

**이 단계에서는 아직 제목을 쓰지 않는다.** 본문의 내부 용어마다
"이 사실을 독자에게 어떻게 설명해야 이해되는가"를 먼저 결정한다.

```
내부 표현: 검산 규칙
독자에게 전달할 의미: AI가 계산한 결과를 그대로 믿지 않고 한 번 더 확인하는 절차

내부 표현: AI 합계 오류
독자에게 전달할 의미: AI가 계산한 합계가 틀렸고 사람이 그 오류를 발견함
```

### STEP C. 각도 결정

번역된 의미를 바탕으로 서로 다른 각도 3~5개를 만든다 (오류 발견 / 검증 방식 /
업무 변화 / 실제 적용 / 결과 …). "문장 형태가 다른 제목"이 아니라 **"메시지가 다른
제목"**이어야 한다. 모든 각도를 억지로 쓰지 않는다 — 가장 명확하고 독자가 이해하기
쉬운 각도를 고른다. 차별점이 없으면 억지로 만들지 않는다.

### STEP D. 제목 생성

선택한 각도로 생성한다. **제목만 읽어도 핵심 상황이 이해되는지를 최우선으로** 확인하고,
후보마다 5절 3-CHECK를 통과시킨다. 통과 후보 중 하나를 `# 제목`에 넣고
추천 3개를 `<!-- 제목 후보: … -->` 주석으로 남긴다.

## 3. REFERENCE EXAMPLE — 품질 기준 참고용

아래 예시는 **문장 템플릿이 아니다.** 실제 표현·문장 구조를 재사용하지 않는다.
참고할 것은 구체성·독자 자립성·본문 고유성·명확한 메시지·자연스러운 한국어·
사실에서 의미를 뽑아내는 방식 — **품질 특성뿐**이다.

* `예제 대신 실제 신고 데이터로 시작한 119 AI 교육`
* `교육이 끝나도 데이터는 상황실에 남는다`
* `의료진 72명이 각자 쓸 도구를 직접 만들었습니다`

## 4. 최종 검증 — 3-CHECK (유일한 판정 기준)

생성·심사 모두 아래 3개 항목**만** 확인한다. 판단 순서는 ① → ② → ③.

### CHECK 1. 독자가 이해할 수 있는가? (P1)

제목만 읽은 사람이 본문 없이 무슨 일이 있었는지 이해할 수 있는가?

FAIL: 내부 용어·전문용어로 의미를 알기 어려움 / 핵심 표현이 맥락 없이는 이해 안 됨 /
구체적 사건·행동 없이 추상적 의미만 전달 / 읽고 나서 "그래서 무슨 일이 있었다는 거지?"
라는 질문이 생김. **구체적인 표현이라도 독자가 이해하지 못하면 FAIL이다.**

### CHECK 2. 본문에 실제 근거와 고유한 내용이 있는가? (P2·P3)

제목의 핵심이 본문에서 확인되고, 이 후기에서만 확인되는 사건·행동·문제·결과·산출물·
도구·변화가 최소 1개 있는가?

FAIL: 본문에 없는 내용을 만들어냄 / `AI 역량 강화`·`업무 효율화`류 범용 표현뿐 /
참가자 수·교육 시간 등 단순 운영정보만으로 구성.

### CHECK 3. 제목으로서 자연스럽고 독립적인가? (P4·P6·P7)

실제 홍보 제목으로 바로 쓸 수 있고, 예시·기존 제목을 흉내 내지 않았는가?

FAIL: 어색한 한국어·과도한 명사 나열 / 본문 문장을 잘라 붙인 느낌 / 키워드 억지 삽입 /
주어·목적어 관계 불명확 / 예시·기존 제목의 문장 구조·수사·핵심 표현 모방 /
`<기관·과정명> — <메시지>` 구조가 아님. (단순한 단어 중복은 모방이 아니다)

### 판정과 재생성

**3개 모두 PASS → 최종 제목. 하나라도 FAIL → 제목 폐기 후 재생성.**

FAIL 시 단어 몇 개만 바꾸지 않는다 (`AI 합계를 검산 규칙대로` → `AI 합계 오류를 검산
규칙으로` 는 재창작이 아니다). 절차:

```
실패 원인 확인 → 본문 재분석 → 다른 구체적 사실 선택(또는 같은 사실의 다른 번역)
→ 독자 언어로 의미 번역 → 다른 관점으로 재생성 → 3-CHECK 재실행
```
