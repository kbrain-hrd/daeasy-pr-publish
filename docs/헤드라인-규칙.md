# 헤드라인 생성 규칙

## 핵심 원칙

헤드라인 생성은 서로 다른 두 작업의 연속이다.

> **① 본문에서 구체적인 사실을 찾는다. ② 그 사실을 본문을 읽지 않은 사람도
> 즉시 이해할 수 있는 독자 언어로 번역한다. 이 둘을 생성 과정에서 명시적으로 분리한다.**

- **구체성** = 본문에 실제 존재하는 특정 사건·행동·문제·결과·변화를 담는 것
- **이해 가능성** = 그 사실을 본문을 읽지 않은 사람도 이해할 수 있는 언어로 표현하는 것
- **본문의 전문용어·내부 업무용어를 그대로 제목에 넣는 것은 구체성이 아니다.**
  내부 용어를 그대로 쓰는 것보다 그 용어가 실제로 무엇을 의미하는지 풀어 쓰는 것이
  더 적절할 수 있다.

①만 하고 ②를 건너뛰면 내부 용어 압축("AI 합계를 검산 규칙대로")이 되고,
②만 의식하면 어느 교육에나 붙는 일반론("AI 역량 강화")으로 후퇴한다.
**최종 제목은 항상 둘을 동시에 만족해야 한다.**

순서는 언제나 **구체적인 사실 → 독자가 이해할 수 있는 의미 → 자연스러운 제목**이다.

## 1. 생성 우선순위 — 위가 아래를 이긴다

하위 조건(특히 P6 형식) 때문에 독자 이해 가능성과 자연스러움을 희생하지 않는다.

### P1. 독자 전달성 (최우선)

제목만 읽은 사람이 본문 없이도 최소한 다음을 이해할 수 있어야 한다:
무슨 일이 있었는지 · 무엇이 특이한지 · 어떤 행동·변화·결과가 있었는지.
본문 내부에서만 통하는 용어·축약어·업무 맥락·과정 내부 명칭을 그대로 압축하지 않는다.

나쁜 방향: `AI 합계를 검산 규칙대로 다시 확인했습니다` — "AI 합계"·"검산 규칙"이 무엇인지 알 수 없다.
좋은 방향: `AI가 계산한 합계의 오류를 직접 찾아냈습니다` — 상황이 그려진다.
(예시 문장의 복제가 아니라 **내부 사실 → 독자가 이해할 수 있는 의미**로 변환하는 것이 핵심)

### P2. 본문 근거·고유성

제목의 핵심 내용은 반드시 본문에서 확인되어야 하고, 동시에 이 교육 후기에서만
확인되는 구체적 사실이 최소 하나 있어야 한다 — 특정 사건·문제·행동·결과·산출물·
도구 활용·업무 변화·실습 장면.

`AI 역량 강화`·`업무 효율화`·`디지털 전환`·`업무 혁신`류 표현만으로 제목을 구성하지
않는다 — 여러 교육 후기에 그대로 붙일 수 있어 고유성이 없다.

### P3. 자연스러운 제목

구체성을 확보한다는 이유로 본문 용어를 무리하게 압축하지 않는다
(`A 합계`·`B 검산 규칙`·`C 업무 프로세스`·`D 적용 기반`·`E 검증 체계`·`F 활용 전략` 류
전문용어 연결 금지). 어색한 의인화·비관용 연어를 만들지 않는다.
**소리 내 읽었을 때 사람이 실제로 말할 법한 자연스러운 한국어**여야 한다.
대구·숫자 반복 같은 말맛을 노리지 않는다 — 평이한 문장이 기본값이다.

### P4. 검색 주제 적합성

기관명·과정명·핵심 주제와 자연스럽게 연결되면 충분하다.
**검색 키워드는 제목 품질을 보조하는 요소이지 최우선 요소가 아니다** —
검색어를 넣기 위해 의미나 자연스러움을 희생하지 않는다.

### P5. 독립성

REFERENCE EXAMPLE(3절)과 기존 발행 제목의 품질 특성은 참고하되 문장 골격·수사 구조·
대비 방식·핵심 어구·표현 조합·문장 패턴을 복제하지 않는다.
단순한 단어 중복만으로 모방이라고 판단하지 않는다.

### P6. 형식 조건 (위 기준 충족 후 검수)

- 구조: **`<기관·과정명> — <헤드라인 메시지>`** — 앞부분은 목록 식별자, 차별성은 줄표 뒤에서
- 60자 이하. 핵심 메시지는 **하나만** (여러 사실의 병렬 나열·수치 과다·중복 표현 금지)
- `기관 + 교육명 + 인원 + 인증`처럼 수치·결과를 늘어놓은 성적표형 금지
  (기관·과정 라벨 자체는 관례라 허용)
- 클릭베이트·과장 금지. 본문에 없는 의미를 보태지 않는다
- 양식의 **희망 헤드라인**이 4절 3-CHECK를 통과하면 메시지로 우선 채택한다(그대로 또는 다듬어서)

## 2. 생성 절차 — 의미 번역을 건너뛰지 않는다

`본문 사실 추출 → 제목 생성` 두 단계로 곧장 가지 않는다. 반드시 아래 순서를 밟는다.

### STEP 1. 본문 사실 추출

제목 소재가 될 수 있는 실제 사실을 사건의 흐름으로 찾는다. 본문에 없는 사실은 추가하지 않는다.

```
AI가 사업실적 합계를 계산함 → 계산 결과에 오류가 발생함 → 사람이 결과를 검토함
→ 오류를 발견함 → 결과를 확인하는 절차를 적용함
```

### STEP 2. 내부 표현과 독자 표현 분리 (의미 번역)

**이 단계에서는 아직 제목을 작성하지 않는다.** 본문의 전문용어·내부 업무용어마다
그대로 제목에 써도 되는지 판단하고, 안 되면 독자에게 전달할 의미를 먼저 결정한다.

```
내부 표현: 검산 규칙
독자에게 전달할 의미: AI가 계산한 결과를 그대로 믿지 않고 한 번 더 확인하는 절차
```

### STEP 3. 제목 각도 선택

번역된 의미를 바탕으로 제목의 관점을 고른다 — 관통형·관찰형·의미 부여형·대비형·
과정형·결과형 등. **각도를 기계적인 제목 공식으로 사용하지 않는다.**
현재 본문에서 가장 명확하고 독자에게 이해하기 쉬운 관점을 선택한다.
차별점이 없으면 억지로 만들지 않는다.

### STEP 4. 제목 생성

`구체적인 사실 → 독자가 이해할 수 있는 의미 → 자연스러운 제목` 기준으로 생성한다.
후보마다 4절 3-CHECK를 통과시키고, 통과 후보 중 하나를 `# 제목`에 넣고
추천 3개를 `<!-- 제목 후보: … -->` 주석으로 남긴다.

## 3. REFERENCE EXAMPLE — 품질 기준 참고용

아래 예시는 **문장 템플릿이 아니다.** 참고할 것은 구체성·독자 자립성·본문 고유성·
명확한 메시지·자연스러운 한국어·사실에서 의미를 뽑아내는 방식 — **품질 특성뿐**이다.
예시의 제목을 템플릿으로 사용하지 않는다.

* `예제 대신 실제 신고 데이터로 시작한 119 AI 교육`
* `교육이 끝나도 데이터는 상황실에 남는다`
* `의료진 72명이 각자 쓸 도구를 직접 만들었습니다`

## 4. 최종 검수 — 3-CHECK (유일한 판정 기준)

생성·심사 모두 아래 3개 항목**만** 사용한다. 판단 순서는 ① → ② → ③.
독립성·내부 용어·검색어·자연스러움·명사 나열 등을 별도 판정 항목으로 만들지 않는다 —
전부 이 3개 안에서 판단한다.

### CHECK 1. 독자 전달성

제목만 읽은 사람이 본문을 읽지 않아도 무슨 일이 있었는지 이해할 수 있는가?

PASS 조건: 핵심 표현의 의미를 맥락 없이 이해할 수 있음 / 실제 사건·행동·변화 중
하나가 제목에서 드러남 / 읽고 나서 "그래서 무슨 말이지?"라는 질문이 생기지 않음.

FAIL: 내부 용어·과도한 압축·추상적인 표현 때문에 독자가 의미를 이해하지 못함
(`AI 합계를 검산 규칙대로 다시 확인했습니다` · `생성형 AI 활용 프로세스를 고도화했습니다` ·
`AI 활용 역량을 강화했습니다`). **구체적인 표현이라도 독자가 이해하지 못하면 FAIL이다.**

### CHECK 2. 본문 근거·고유성

제목의 핵심 내용이 본문에 실제로 존재하고, 이 후기만의 구체적 사실
(특정 사건·문제·행동·결과·산출물·도구·업무 변화)이 최소 1개 있는가?

FAIL: 본문에 없는 내용을 만들어냄 / 작성자의 추측을 사실처럼 사용함 /
`AI 역량 강화`·`업무 효율화`류 일반적인 표현만 사용함 /
참가자 수·교육 시간 등 단순 운영정보만으로 구성.

### CHECK 3. 제목 품질·독립성

실제 홍보 콘텐츠의 제목으로 쓸 수 있을 만큼 자연스럽고, 기존 예시나 제목을 모방하지 않았는가?

FAIL: 어색한 한국어 / 과도한 명사 나열 / 본문 문장을 단순히 잘라 붙인 느낌 /
검색 키워드를 억지로 삽입한 느낌 / 주어·목적어 관계 불명확 / 지나치게 기계적인 표현 /
REFERENCE EXAMPLE·기존 게시물 제목의 문장 구조·수사 방식 모방 /
`<기관·과정명> — <메시지>` 구조 위반·60자 초과 / 실제 홍보 제목으로 사용하기 어려움.
(단순한 단어 중복은 모방으로 판단하지 않는다)

### 최종 판정과 FAIL 처리

**3개 모두 PASS → 최종 제목. 하나라도 FAIL → 최종 제목으로 사용하지 않는다.**

FAIL이 나면 기존 제목을 조금 수정해서 통과시키지 않는다
(`검산 규칙대로` → `검산 방식으로` 같은 단어 교체는 허용하지 않는다). 절차:

```
FAIL 원인 확인 → 기존 제목 폐기 → 본문의 다른 구체적 사실 재탐색
→ 내부 표현과 독자 표현 분리 → 사실의 의미를 독자 언어로 재번역
→ 다른 제목 각도 선택 → 새 제목 생성 → 3-CHECK 전체 재실행
```
