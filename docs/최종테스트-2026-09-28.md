# 자동발행 파이프라인 최종 테스트 기록 (2026-09-28)

개인 네이버 계정 기준 end-to-end 검증. 이 기록을 끝으로 시스템은
**회사 계정 전환 → 실제 접수 건 파일럿** 단계로 넘어간다.

- 테스트 건: 한빛지역진흥원 목데이터 (사진 1장 임베드, 회차 1기)
- 실행 흐름: `DOCX+사진 → intake → research → write → 품질 루프 → 교정 → 최종 검증
  → 사이트 draft → naver.md 변환 → SmartEditor 작성 → 발행 직전 정지`
- 발행 정책: 사이트 draft까지 · 네이버 발행 직전 정지까지 자동, 실제 공개는 사람
  (`publish.site: false` · `--publish` 코드 차단)

## 2. 테스트 중 발견·수정한 이슈 (전부 봉합)

| 이슈 | 원인 | 수정 |
|---|---|---|
| slug `-h2` 임의 추론 | LLM이 9월+기존 사례(h1)에서 "하반기" 추론 | `slug_rules.py` 신설 — 조각별 근거 검증 (숫자=연도/회차 필드, 라틴=필드 영문/로마자 전사/통용 어휘, h1·h2/서수/test류 무조건 탈락). fallback(폴더명 URL) 경로 봉쇄 |
| 본문·교육 개요 나눔고딕 | 컴포넌트(사진·목록·인용·구분선) 진입/이탈 시 에디터가 계정 기본 글꼴로 리셋 | 컴포넌트 진입 전후 기본서체 재고정 + 이미 기본서체면 드롭다운 안 엶 + 열린 드롭다운은 finally에서 반드시 닫음 |
| 공식 멘트 구분 약함 → 인용구 전환 후 발행 실패 | 문서 끝 인용구의 "아래 +60px 탈출 클릭"이 하단 고정 **글감 검색 바**를 눌러 글감 패널(se-popup-unified-result-flayer)이 열리고 dim이 모든 클릭을 가로챔 | 탈출 클릭 전 인용구를 화면 중앙으로 스크롤 + 패널 열리면 즉시 Escape. 실패 시 화면 자동 캡처(`naver_글꼴실패.png`) 진단 장치 추가 |

## 3. NAVER API HUB 사용처 (추적 확정)

| 항목 | 확인 결과 |
|---|---|
| 실제 사용 | 자동발행 파이프라인 **미사용** — 수동 검색 전용 |
| 호출 코드 | `scripts/search_kr.py` `naver()` 한 곳 (env: NAVER_CLIENT_ID/SECRET, NAVER_API_BASE, NAVER_ID_HEADER/SECRET_HEADER) |
| 호출 API | `GET naverapihub.apigw.ntruss.com/search/v1/{news·blog·cafearticle·webkr}` — 검색 API |
| 파이프라인 관계 | research의 기본 검색 갈래는 `korea,kakao` — naver는 `--only naver` 수동 시만. 2026-09-07 개정 약관(검색 결과 AI 입력 금지)에 따라 LLM 투입 금지 |
| 블로그 발행과의 관계 | **완전 별개** — SmartEditor는 `.naver-profile/` 브라우저 로그인 세션, HUB는 HTTP 헤더 키. `prpub/naver.py`에 API 키 사용 0건 |
| 회사 전환 시 | 블로그 발행은 `uv run prpub naver-login`으로 **로그인 세션만 회사 계정으로 교체하면 끝**. HUB 키는 전환 필수 아님 — 회사 명의가 필요해지면 회사 네이버클라우드 계정에서 별도 발급 후 `.env` 2줄 교체 (키는 계정 귀속, 이관 불가) |

## 4. 남은 단계

1. **회사 계정 전환**: `uv run prpub naver-login` → 회사 계정 로그인 (개인 세션 보존이 필요하면 `.naver-profile/` 폴더를 먼저 복사)
2. **실제 접수 건 파일럿**: 접수함에 실제 양식 투입 → 두 채널 발행 직전까지 확인 → 사람이 공개/발행
3. 정리(선택): 한빛 목데이터·구양식 목데이터 접수함 정리, 테스트 draft·임시글 삭제
4. 장기: 실운영 안정 확인 후 정지점 제거(완전 자동발행 전환 — `publish.site: true` + 네이버 `--publish` 허용), 카카오 검색 약관 확정
