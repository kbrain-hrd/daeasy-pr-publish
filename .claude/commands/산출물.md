새 교육산출물을 보관본으로 만든다. 아래 순서를 **그대로** 따르고, 각 단계 결과를 짧게 보고한다.
배경과 함정은 `output-archive/CLAUDE.md` 에 있다. **시작 전에 반드시 읽는다.**

원본이 살아 있을 때만 할 수 있는 작업이다. 미루지 않는다.

## 0. 대상 확인

인자로 원본 주소를 받는다. 없으면 데이지 홈페이지(https://daeasy.vercel.app)의
교육산출물 항목에서 "프로토타입 직접 살펴보기" 링크를 찾아 후보를 보여주고 고르게 한다.

이미 `output-archive/sites.json` 에 있는 주소면 **다시 뜰지** 먼저 묻는다.
다시 뜨면 그 시점의 데이터로 갱신되고, 이전 보관본은 덮인다.

## 1. 등록

`output-archive/sites.json` 에 항목을 추가한다 — 슬러그·title·origin·course·captured(오늘 날짜)·routes.

`routes` 는 원본 첫 화면 HTML 에서 찾는다. `"/xxx"` 패턴을 뽑거나 사이드바 링크를 본다.
빠뜨리면 그 화면이 통째로 보관되지 않으니 꼼꼼히 본다.

## 2. 내려받기

```
uv run python output-archive/tools/mirror.py <슬러그>
```

라우트별 HTML · assets · `_serverFn` 응답을 받는다.
**서버함수가 405 로 실패하는 것은 정상이다** — 입력을 받아야 하는 함수라 미리 뜰 수 없다.
몇 개가 실패했는지 기억해둔다. 5단계에서 그만큼 기능이 죽어 있을 것이다.

## 3. lovable 흔적 제거

```
uv run python output-archive/tools/strip_lovable.py <슬러그>
```

배지·추적 스크립트를 지우고 미리보기 이미지를 내려받는다. 바깥으로 나가는 요청을 남기지 않는다.

## 4. 보정 스크립트 주입

```
uv run python output-archive/tools/inject.py <슬러그>
```

## 5. 띄워서 직접 눌러본다 — 이 단계를 건너뛰지 않는다

```
uv run python output-archive/serve.py <슬러그> [포트]
```

브라우저로 열어 **모든 화면을 실제로 클릭해본다.** 최소한 이만큼은 확인한다.

- 사이드바·상단의 **모든 메뉴로 이동**해본다 (첫 화면만 보고 판단하지 않는다)
- 탭·필터·카테고리를 **전환**해본다
- 표의 **정렬·검색·페이지 이동**을 눌러본다
- 지도가 있으면 **끌고 확대하고 도형을 클릭**해본다
- 입력창이 있으면 **뭐라도 넣고 실행**해본다
- 콘솔 오류를 읽는다

**주의**
- 화면이 이상하면 **브라우저 캐시부터 의심한다.** 주소에 `?v=2` 를 붙여 다시 부른다.
- 이전 방문 기록(localStorage)이 남아 하이드레이션 오류가 나기도 한다. 비우고 다시 본다.
- **원본과 비교한다.** 비어 있는 차트나 안 눌리는 버튼이 원본에도 그런지 확인한다.
  원본도 그렇다면 고치려 들지 않는다. 그건 산출물이 원래 그런 것이다.

무엇이 되고 무엇이 안 되는지 **목록으로 정리해 보고한다.**

## 6. 안 되는 것을 어떻게 할지 묻는다 — 혼자 정하지 않는다

5단계에서 나온 문제를 유형별로 정리해 **선택지와 함께 예진님께 묻는다.**

**지도가 빈칸이면** — 원본이 구글 지도를 쓰는데 API 키가 원래 도메인에 묶여 있어서다.
`offline/gmaps.js` 어댑터로 대체할 수 있다. 받아둘 지역 범위와 확대 수준을 정해야 하니
예상 용량과 함께 물어본다. (영등포구 z13~16 기준 708장 19MB)
정해지면 `sites.json` 에 `map` 을 넣고 `tools/tiles.py` 를 돌린 뒤 `inject.py` 를 다시 돌린다.
**`gmaps.js` 의 `BOUNDS` 와 `sites.json` 의 `map.bounds` 를 같은 값으로 맞춘다.**

**AI 기능이 죽어 있으면** — 답변은 질문이 들어와야 만들어지는 것이라 미리 뜰 수 없다.
원본이 살아 있는 동안 대표 입력의 결과를 저장해두면 그것만은 동작한다.
**할지 말지, 한다면 어떤 입력으로 할지 예진님께 묻는다.** 질문 목록을 임의로 정하지 않는다.
하기로 하면 `sites.json` 에 `record` 를 넣고 `tools/record.py` → `tools/patch_examples.py` 순으로 돌린다.

**그 밖에 깨진 것** — 원인을 찾아 보고하고 어떻게 할지 묻는다.

## 7. 저장소 반영

`output-archive/` 안의 변경만 담아 커밋한다. **다른 폴더의 변경은 섞지 않는다** —
예진님이 작업 중인 파일이 있으면 스테이징에서 뺀다.

커밋 메시지에는 무엇이 되고 무엇이 안 되는지 적는다.
push 는 빌드가 필요 없으므로 바로 한다.

## 8. 확인 문서 (요청이 있을 때만)

보고용이 필요하다고 하면 `output-archive/docs/` 에 화면 캡처를 담은 단독 html 을 만든다.
기존 파일(`보관본-동작확인_2026-09-01.html`)을 본으로 삼는다.

- 커밋 해시

## 하지 않을 것

- 원본에 없던 요소를 화면에 더하지 않는다. 안내 문구·배너를 임의로 넣지 않는다.
- `sites/` 안의 파일을 손으로 고치지 않는다. `tools/` 를 고치고 다시 뜬다.
- 예진님이 요청하지 않은 개선을 제안하며 진행을 늘리지 않는다.
