---
description: 접수함의 홍보자료 양식을 검증하고 게시글을 작성해 daeasy 사이트에 일괄 발행한다
---

접수함에 쌓인 홍보자료를 한 번에 발행한다. 아래 순서를 **그대로** 따르고, 각 단계 결과를 짧게 보고한다.

## 1. 검사
`uv run prpub scan` 을 실행해 접수 건 목록과 검증 결과를 보여준다.
- ❌ 건은 오류 내용을 그대로 보여주고 **이번 발행에서 제외**한다. 등록자에게 전달할 수정 요청 문구를 한 줄로 만들어준다.
- 접수함이 비어 있으면 여기서 끝낸다.

## 2. 패키지 생성
`uv run prpub build <폴더명...>` 으로 통과한 건만 빌드한다. `out/{slug}/` 에 `brief.md`(등록 내용 정리), `meta.json`, `images/`, `files/` 가 생긴다.

## 3. 사진 (LLM 이 정한다)
`images/` 의 사진을 하나씩 **직접 열어 보고** (Read) 각 사진에 한 줄 캡션을 붙인다. 대표 사진은 교육 장면이 잘 드러나고 얼굴이 크게 나오지 않은 것으로 고른다. 결과를 `out/{slug}/photos.md` 에 `번호 · 파일 · 캡션 · 대표 여부` 로 기록한다.

여기서 보는 것은 **접수함에 들어온 우리 사진뿐**이다. 외부 기사·보도자료 사진과 관련 링크는 **5단계**에서 `정보수집` 에이전트가 찾는다. 여기서 미리 웹을 뒤지지 않는다 — 초안이 나와야 무엇이 빠졌는지 알고 찾을 수 있다.

## 4. 정보수집 — 글쓰기 전에 재료를 모은다

**글을 쓰기 전에 재료를 다 모은다.** 양식만 보고 쓰면 그 안에 있는 것밖에 못 쓴다.
재료가 결과를 가른다는 것이 문헌에서 확인된 사실이다 (Can Good Writing Be Generative, CHI 2026).

### 4-1. 조사

`정보수집` 에이전트를 부른다. `out/{slug}` 을 알려준다.

에이전트는 `brief.md` 를 읽고 그 교육을 다룬 기사·기관 보도자료를 찾아
`out/{slug}/research.md` 를 만든다. 저작권이 확인된 사진은 `images/외부/` 에 내려받는다.
**글을 쓰지 않는다** — 대조할 원자료를 남기는 것이 이 단계의 일이다.

자료를 못 찾으면 그대로 다음 단계로 간다. **없는 것을 지어내 보태지 않는다.**

### 4-2. 쓸 것만 고른다

`research.md` 를 보고 **글에 넣을 것만 고른다.** 에이전트가 찾아왔다고 다 쓰지 않는다.

넣을 때 지킬 것:

- **확신 낮음으로 표시된 자료는 넣지 않는다.** 사람이 따로 확인한 뒤에나 쓴다
- **수치는 EMS 가 기준이다.** 기사 숫자가 다르면 EMS 쪽을 쓴다.
  다만 **EMS 에 그 기수가 없으면 양식이 기준이다.** 실제로 진행된 교육이면 EMS 에 없어도 그대로 쓴다 —
  다른 팀이 진행한 외부 행사·기관 단위 교육은 EMS 에 안 들어와 있다
- **인용문은 원문 그대로.** 누가 언제 한 말인지 밝힌다
  - 기사 본문을 통째로 옮기지 않는다. 짧은 인용까지다.
    "장관이 이렇게 말했다" 같은 **사실 자체는 저작권 대상이 아니니** 우리 문장으로 다시 쓴다
- **사진**은 `research.md` 에 적힌 출처 문구를 캡션에 그대로 넣는다 (`(사진 = 화성시)`).
  공공누리 **제3유형**은 자르거나 보정하지 않는다
- 쓰기로 한 외부 사진은 `photos.md` 에 추가한다
- **같은 사진을 두 번 쓰지 않는다.** 대표 사진으로 쓴 것을 본문에 또 깔면 글이 반복돼 보인다.
  사진이 한 장뿐이면 대표로만 쓰고 본문에는 넣지 않는다 — `score.py` 와 `preview.py` 가 막는다
- 글 끝에 **`## 이런 글도 있습니다`** 를 두고 **데이지 교육후기 다른 게시물 2건**을 URL 만 한 줄씩 적는다.
  `scripts/preview.py` 가 그 글의 **첫 번째 본문 사진**을 썸네일로 떠서 정사각 카드 2열로 그린다.
  이 형식은 고정이다. 96px 정사각 썸네일 + 제목 두 줄 + 도메인 한 줄.
  화면이 무너져 보이면 `docs/preview/daeasy.css` 가 없어서다 — `preview.py` 가 자동으로 다시 받아 온다.
  - 링크는 `https://daeasy.co.kr/cases/<slug>` 다. 지금 올라간 글 목록은 `https://daeasy.co.kr/cases` 에서 확인한다
  - **바깥 기사·보도자료는 카드로 걸지 않는다.** 기관 사이트는 글별 썸네일이 없어 로고만 나온다.
    출처는 본문 문장 안에 밝힌다 (`행정안전부가 6월 17일 낸 보도자료에 실린 말입니다`)


## 5. 게시글 작성

4단계에서 모은 `brief.md` · `research.md` · `photos.md` 를 모두 읽고 쓴다.
**채점은 여기서 하지 않는다.** 6단계 1차 검수가 잰다.

### 5-0. 발견 한 줄 — 못 채우면 여기서 멈춘다

`brief.md` 와 `research.md` 를 읽고 아래를 채워 `out/{slug}/insight.md` 에 적는다.

```
이 교육이 다른 회차와 달랐던 점: ______
그것을 보여주는 증거: ______
```

**채울 수 없으면 글을 쓰지 않는다.** 양식이 부실하면 등록자에게 보완을 요청하고,
정말 특별할 게 없는 회차면 사실 위주 짧은 글로 끝낸다. 없는 특별함을 지어내지 않는다.

### 5-1. 초안

아래 규격대로 `post.md`(사이트) 와 `naver.md`(네이버) 를 쓴다.
**한 번에 완성하려 하지 않는다.** 같은 프롬프트로 써도 품질이 들쭉날쭉하고
(Wordcraft, IUI 2022), 채점과 고쳐쓰기를 거쳐야 좋아진다 (AI-Slop to AI-Polish, 2025).

### 5-2. 규격

각 `brief.md` + `photos.md` 를 읽고 **게시글을 직접 쓴다** → `out/{slug}/post.md`:
- 형식: 맨 위 `# 제목`, 아래 본문. 제목 후보 주석은 5-3 에서 남긴다.
- 문체 (기본): **교육후기체** — daeasy 사이트 `/cases` 에 올라가는 글의 문체다. 기준은 실제 게시글 `킨텍스에서 보낸 이틀, 2026 AI챔피언 해커톤 현장 이야기`.
  - 화자는 **"저희"(데이지)**, 종결은 존댓말 `~습니다`. 교육을 운영하고 온 사람이 현장에서 본 것을 전하는 톤이다. 보도자료의 `~했다/~이다`, 블로그의 `~했어요`를 쓰지 않는다.
  - **제목은 본문을 다 쓴 뒤에 붙인다.** 초안에는 임시 제목을 달아두고, 본문이 끝나면
    5-3 을 따라 `# 제목` 을 고쳐 쓴다. 본문을 읽어야 나오는 것이 제목이기 때문이다.
  - 첫 문단은 `지난 <날짜>, 저희는 <장소>에 있었습니다` 로 시작해 언제·어디서·누가·무엇을 한 문단에 담는다.
  - **`## 소제목` 으로 본문을 나눈다. 최소 2개.** 사이트가 이 H2로 우측 목차를 만들기 때문에 없으면 목차가 비어 보인다. 소제목은 명사 나열(`교육 성과`, `참여자 반응`)이 아니라 **글의 한 대목을 가리키는 말**로 쓴다 (예: `"엑셀만 쓰다가 눈이 트였다"`, `샘플 데이터를 쓰지 않았습니다`). 길이는 10~25자.
  - **소제목은 그 절의 주제와 정확히 맞아야 한다.** 절의 첫 문단이 아니라 **그 절이 무엇에 관한 글인지**를 가리킨다.
    쓰고 나서 그 절만 다시 읽어보고, 소제목이 다른 절에 붙여도 말이 되면 잘못 뽑은 것이다.
    (예: 수상 팀 이야기를 하는 절에 `기관을 섞은 팀이 상을 받았습니다` 는 설명 문단의 제목이지 그 절의 제목이 아니다.
     `화성시와 국민권익위가 한 팀이었습니다` 처럼 그 절에만 붙는 말로 쓴다.)
    설명 문단이 소제목과 안 맞으면 **소제목을 고치거나 그 문단을 맞는 절로 옮긴다.**
  - **핵심 문장은 `**굵게**` 로 강조한다.** 절마다 하나쯤, 독자가 그 대목에서 가져갈 사실이다.
    수치·결과·전환점이 주로 해당한다 (`그중 8팀이 24일 결선에 올랐습니다`, `결선 8팀 가운데 4위`).
    한 문단에 여러 개를 칠하지 않는다. 다 강조하면 아무것도 강조되지 않는다.
    **조사는 강조 안에 넣지 말고 바로 붙여 쓴다** — `**'…사업'**을` 이지 `**'…사업'** 을` 이 아니다.
    (원고에 공백이 있어도 `preview.py` 가 붙여 내보내지만, 원고부터 바르게 쓴다.)
  - 참가자·관계자의 말은 문단 안에 자연스럽게 녹이거나, 무게가 있으면 한 줄로 떼어 강조한다.
  - 숫자는 한 문단에 몰아 담되 성적표처럼 늘어놓지 않는다.
  - 마지막 문단은 **다음 교육으로의 초대**로 맺는다 (예: `다음 무대에 오를 분들을 데이지 AI챔피언 교육에서 기다리겠습니다.`). 사이트가 본문 뒤에 "교육 문의" CTA 를 자동으로 붙이므로 본문에 문의처를 적지 않는다.
  - **한 문단에 2~4문장을 담는다.** 문장마다 줄을 바꾸면 문단 여백이 계속 생겨
    글 전체가 한 줄씩 띄운 목록처럼 보인다. 사이트에 올라간 글들은 문단당 2~5문장이다.
    ```
    ✗  전원 인증이 갑자기 나온 결과는 아니었습니다.
       (빈 줄)
       정보기획팀은 그동안 …을 추진하고, …을 운영해 왔습니다.

    ○  전원 인증이 갑자기 나온 결과는 아니었습니다. 정보기획팀은 그동안 …을
       추진하고, …을 운영해 왔습니다.
    ```
    문단을 나누는 것은 **화제가 바뀔 때**다. 숨 쉬라고 나누지 않는다.
  - **분량은 정해두지 않는다.** 양식에 적어준 만큼 쓴다 — 재료가 많으면 길어지고 적으면 짧아지는 것이 맞다.
    다만 재료가 없는데 길이를 늘리려고 없는 이야기를 지어내지 않는다. 짧은 글이 지어낸 글보다 낫다.
- 사진 캡션은 `<장면 설명>. (사진 = <제공처>)` 형식으로 쓴다. 제공처를 모르면 괄호를 생략한다.
- **네이버 해시태그** — `naver.md` 앞머리의 `태그:` 에 12~16개를 아래 묶음대로 채운다. 검색으로 사람이 찾아올 말을 넣되, **교육에 실제로 있었던 것만** 쓴다. 다루지 않은 기술·유행어를 유입 목적으로 붙이지 않는다.
  | 묶음 | 넣을 것 | 출처 |
  |---|---|---|
  | 브랜드 (항상) | `데이지` `DAEASY` `케이브레인컴퍼니` `공공기관AI` | 고정 |
  | 기관 | 기관명, 통칭이 따로 있으면 함께 (`부산시` `부산시청`) | `meta.json` 교육 기관 |
  | 과정 | 과정명과 그 상위 이름 (`AI챔피언` `AI챔피언그린`) | 교육과정 |
  | 주제 | 실제로 다룬 도구·산출물 (`챗GPT활용` `민원데이터` `대시보드`) | 다룬 주제 · 실습 결과물 |
  | 대상 | 참여자를 부르는 말 (`공무원교육`) | 참여 인원·대상 |
  | 마무리 | `업무혁신` `디지털전환` 중 1~2개 | 고정 후보 |
  - 띄어쓰기 없이 붙여 쓰고, **앞머리 `태그:` 와 본문 맨 끝 `#태그` 양쪽에 모두 적는다.**
    - 앞머리 것은 발행 팝업의 "태그 편집"에 등록돼 **네이버 태그 검색에 걸린다.** 기존 글들은 이걸 안 해서 검색 노출을 받지 못했다.
    - 본문 끝 것은 이 원고를 **인스타그램·유튜브에 그대로 옮겨 쓸 때** 필요하다. 그쪽은 본문 해시태그가 유일한 수단이다.
- **함께 보면 좋은 글** — 맺음 블록 바로 앞에 daeasy 사이트 교육후기 **2편**을 붙인다.
  네이버는 URL 만 적으면 **썸네일과 제목이 붙은 링크 카드를 자동으로** 만든다.

  ```
  ──────────

  함께 보면 좋은 글

  https://daeasy.vercel.app/cases/<slug1>
  https://daeasy.vercel.app/cases/<slug2>
  ```

  고르는 법 — `https://daeasy.vercel.app/cases` 목록을 열고 **이번 글과 이어지는 것**을 고른다.

  | 우선 | 무엇 |
  |---|---|
  | 1 | **같은 과정의 다른 회차** — 그린 3회차 글이면 그린 다른 회차 |
  | 2 | **같은 기관·부문** — 공공기관 글이면 공공기관 |
  | 3 | **비슷한 주제** — 생성형 AI, 데이터 분석 등 |

  최신순으로 아무거나 넣지 않는다. **이번 글을 읽은 사람이 다음으로 읽을 만한 것**을 고른다.
  이번 글 자신은 넣지 않는다. 사이트에 글이 2편뿐이면 1편만 넣는다.

- **네이버 글 맺음 구조** — 본문은 앞부분만 보여주고, 뒤에 링크 카드 3장을 깐다.
  URL 만 있는 줄은 스마트에디터가 **썸네일 링크 카드**로 바꾼다 (`prpub/naver.py` 의 `linkcard` 블록).
  ```
  ──────────

  함께 보면 좋은 글

  https://daeasy.co.kr/cases/<다른 교육후기 1>

  https://daeasy.co.kr/cases/<다른 교육후기 2>

  ──────────

  교육 문의

  조직에 맞는 AI·데이터 교육 도입을 상담한다. 사전 인터뷰 뒤 맞춤 커리큘럼 제안서를 일주일 안에 보낸다.

  https://daeasy.co.kr/contact

  운영사: (주)케이브레인컴퍼니
  브랜드: 데이지(DAEASY)
  이메일: data-edu@kbrainc.com
  SNS: instagram.com/daeasy.official
  ```
  - 소제목은 **`함께 보면 좋은 글`** 과 **`교육 문의`** 로 고정한다
  - 도메인은 **`daeasy.co.kr`** 이다 (`daeasy.vercel.app` 은 옛 주소)
  - 맺음 블록에 홈페이지 줄을 따로 적지 않는다 — 위 `contact` 카드가 그 자리를 대신한다
- **강조 카드** — 글에서 가장 무게 있는 것 하나씩만 카드로 뽑는다. 사진을 대신하는 장식이 아니라 핵심을 세우는 장치다.
  - `::인용 <말>|<누가·언제>::` — 글 전체에서 **한 개만**. 제목이나 소제목으로 이미 쓴 말은 카드로 또 쓰지 않는다. 나머지 인용은 본문 문장 안에 둔다.
  - `::수치 <값> · <라벨>|<값> · <라벨>|…::` — 글 전체에서 **한 개만**, 항목은 3~4개. `meta.json` 의 참여 인원·인증 결과·만족도·결과물 수에서 가져오고, 없는 수치는 만들지 않는다.
  - 양식에 인용할 말이 없거나 내세울 수치가 없으면 그 카드는 쓰지 않는다. 두 카드 다 없어도 된다.
  - **사진이 한 장도 없는 건**도 카드로만 채운다. 대표 사진 자리는 비워 두고, 카드 개수는 늘리지 않는다 — 사진이 없다고 카드를 더 넣으면 글이 카드 목록처럼 보인다.
- 사용자가 "뉴스기사체"를 지정하면 그 톤으로: `~했다/~이다` 종결, 역피라미드(첫 문단에 누가·언제·어디서·무엇을·규모), 수치 우선, 제목은 `기관, 핵심 사실… 수치` 구조, 인용은 `참여자들은 "…"는 반응을 보였다` 형식, 마지막 문단은 데이지 공식 소개로 맺는다. `데이지 관계자는 …라고 밝혔다` 같은 **가짜 발언 귀속은 금지**.
- 구성: 첫 문단은 01 기본 정보(누가·언제·어디서·무엇을), 둘째 문단부터 02 교육 내용(특별했던 점·결과물), 수치, 03 참여자 반응 순. "강조할 점"이 있으면 그 메시지를 맺음 문단 직전에 담는다.
- **사실의 선**: 양식에 적힌 사건·장면·말만 사실로 쓴다. 없는 대화, 없는 장면("30분쯤 지나자 질문이 나왔다" 류), 없는 인물 묘사("십 년 넘게 엑셀 쓴 분")를 만들지 않는다. 대신 다음은 써도 된다 — (a) 과정이 일반적으로 다루는 내용의 설명("이 과정은 …을 순서대로 다룹니다"), (b) daeasy 공식 소개 문구(행안부 AI챔피언 운영기관, "실제 조직의 데이터와 문제를 가지고 풀어내는 프로젝트 기반 학습" 등 사이트에 있는 것), (c) 사실에서 바로 나오는 해석("도구가 바뀐 게 아니라 데이터를 보는 방식이 바뀐 것").
- "참가자가 한 말"이 있으면 **원문 그대로 인용**한다(따옴표 안 문장을 고치지 않는다). 없으면 반응 문단을 쓰지 않는다.
- 필수 항목만 채워진 건은 (a)(b)로 살을 붙이되, 억지로 늘리지 않는다. 검사 경고("사실 나열 위주")를 사용자에게 같이 보여준다.
- 사진은 `photos.md` 캡션으로, 대표 사진을 첫 이미지로 배치한다. 관련 링크는 5단계에서 나오므로 여기서는 비워 둔다.
- 작성 후 **제목·첫 문단·인용문**을 사용자에게 보여주고 확인받는다.


### 5-3. 제목 — 본문을 다 쓴 뒤에 붙인다

**제목은 글쓰기의 일부다.** 따로 에이전트를 부르지 않고, 별도 파일로 빼지도 않는다.
`post.md` 와 `naver.md` 맨 위의 `# 제목` 이 그 글의 헤드라인이다.

`docs/헤드라인-규칙.md` 를 읽고 그대로 따른다. 요지는 이렇다.

- 본문에서 소재를 찾은 뒤 **의미로 재구성한다.** 본문 문장을 그대로 옮기지 않는다
- **관통형을 먼저 시도한다** — 에피소드 하나가 아니라 글 전체가 말하는 것을 한 문장으로
- **본문을 안 읽은 사람이 한 번에 이해되는가**를 마지막에 확인한다.
  본문을 알아야 뜻이 통하는 비유·대구는 버린다
- `기관명 + 교육명 + 인원 + 인증` 조합은 쓰지 않는다. 그 정보는 부제로 보낸다

후보 10개를 만들어 그중 하나를 `# 제목` 에 넣고,
**추천 3개를 본문 끝 `<!-- 제목 후보: … -->` 주석으로 남긴다.**
사용자가 다른 것을 고를 수 있어야 한다.

붙이기 전에 두 가지만 확인한다.

- **본문에 있는 사실인가.** 없는 장면·수치가 제목에 들어가면 6-2 에서 걸린다
- **60자 이하인가.** 넘으면 차단 검사에 걸린다

제목에 기관명이 앞쪽에 없으면 `score.py` 검색 노출에서 1.0 이 깎인다.
**그렇다고 기관명을 억지로 넣지 않는다.** 사이트 기존 글들이 그렇듯
기관명·과정명·인원은 부제에 담아 보완한다.

## 6. 검수 — 두 번 본다

**수치가 틀린 홍보글은 나가면 안 된다.** 그래서 채점을 통과한 글도 두 번 더 본다.

- **6-1 루브릭 채점** — 글이 값어치가 있는가. 미달이면 5단계로 되돌린다
- **6-2 `글검수`** — 쓴 것이 사실인가. 원자료·EMS 와 대조한다
- **6-3 `발행검수`** — 1차를 믿지 않고 다시 본다. 최종 승인

### 6-1. 1차 — 루브릭 채점

```
uv run python scripts/score.py out/{slug}
```

차단 검사 · 검색 노출 점수 · 문체 지표가 나온다. **그리고 빈 7항목 채점표를 띄운다.**

> ⚠️ **`score.py` 의 "차단 검사: 통과" 만 보고 넘어가지 않는다.**
> 그 줄은 2절 차단 검사일 뿐이고, 3절 7항목 채점은 **코드가 못 센다.**
> 출력 맨 아래 빈 표의 칸을 하나씩 채워 합계를 내고, **항목별 점수와 깎인 이유를 사용자에게 보여준다.**
> 표를 채우지 않았으면 채점을 한 것이 아니다. (실제로 건너뛴 적이 있다 — 8/14 짜리 글이 통과할 뻔했다)

여기에 **7항목 채점**을 더한다.
기준표는 `docs/홍보글-루브릭.md` 3절이다. 각 항목을 **0 · 1 · 2** 로 매긴다.

| # | 항목 | 누가 채점 |
|---|---|---|
| 1 | 대체 불가능성 — 기관명·날짜를 지우고 읽었을 때 이 회차를 특정할 사실이 몇 개인가 | 직접 |
| 2 | 출처 추적성 — 출처를 짚지 못하는 문장이 몇 개인가 | 직접 |
| 3 | 현장 증거 — 그 자리에 있던 사람만 아는 것의 밀도 | 직접 |
| 4 | 검색 노출 — `score.py` 의 점수를 그대로 환산 (4.0↑ = 2 / 2.5~3.5 = 1 / 2.0↓ = 0) | 코드 |
| 5 | 사람 문체 — 상투어·헤징은 코드가 세고, 과하게 꾸민 문장은 직접 | 코드+직접 |
| 6 | 군더더기 없음 — 빼도 되는 문단, 같은 내용 반복 | 직접 |
| 7 | 구성 — 맥락 → 무엇을 했나 → 무엇이 남았나 | 직접 |

**합계를 사용자에게 항목별로 보여준다.** "12점"만 말하지 않고 어디서 깎였는지 적는다.

#### 통과선과 되돌리기

**14점 만점. 12점 이상이면 통과한다.**

아래면 고쳐 쓰고 다시 채점한다. 최대 3회.

- 차단 검사에 하나라도 걸림
- **1번(대체 불가능성)이 0점** — 합계와 무관하게 재작성한다
- 합계 11점 이하

#### 어디까지 고칠 것인가 — 범위를 먼저 정한다

**점수가 낮다고 글 전체를 다시 쓰지 않는다.** 문제가 난 곳만 고친다.
전체 재작성은 멀쩡하던 문단까지 흔들어 다른 항목이 새로 깎이고, 시간도 몇 배 든다.

| 무엇이 깎였나 | 고치는 범위 |
|---|---|
| 제목이 조합형·요약형 (4번, 또는 사용자 지적) | **제목만** 고친다 (아래 참조) |
| 원자료에 없는 사실·수치 (차단 검사, 2번) | **그 문장만.** 근거가 없으면 문장을 뺀다. 주변 문단을 건드리지 않는다 |
| 문단당 문장이 적음 · 문단 여백 (문체 지표) | **해당 문단만** 합치거나 나눈다 |
| 상투어·헤징·과하게 꾸민 문장 (5번) | **그 문장만** 고쳐 쓴다 |
| 뺄 문단·중복 (6번) | **그 문단만** 삭제한다 |
| 소제목이 절 내용과 안 맞음 (7번) | **소제목만** 고치거나 그 문단을 맞는 절로 옮긴다 |
| 검색 노출 항목 (4번) | **첫 문단·소제목·태그·링크만** 손본다. 분량을 늘리려 문단을 붙이지 않는다 |
| 현장 증거가 없음 (3번) | **재료 부족이다.** 글이 아니라 4단계 정보수집으로 돌아가거나 등록자에게 보완을 요청한다 |
| **대체 불가능성 0점 (1번)** · 구성이 흐트러짐 (7번) | **여기서만 전체를 다시 쓴다.** 글의 뼈대가 잘못 잡힌 경우다 |

고친 뒤에는 **`score.py` 를 다시 돌리고 7항목을 다시 매긴다.** 고친 자리가
다른 항목을 깎지 않았는지 봐야 하기 때문이다.

**제목을 고칠 때** — "후보를 다시 뽑는다"가 아니라 **규칙에 따라 다시 쓰는 것**이다.
그냥 다시 뽑으면 본문에서 눈에 띄는 문장을 집어 오게 되고, 사실 서술형으로 되돌아간다
(`119 상황실이 지난해 신고 기록을 들고 교육에 왔습니다` 가 그렇게 나왔다).

1. **제목만 손댄다.** 본문은 건드리지 않는다
2. `docs/헤드라인-규칙.md` 를 **다시 읽고 그 절차대로 재작성한다**
3. 본문을 단순 요약하거나 **본문 문장을 그대로 옮기지 않는다**
4. `기관명 + 교육명 + 인원 + 인증 결과` 의 단순 조합을 쓰지 않는다
5. 고친 뒤 **전체를 다시 채점한다**

고칠 때는 전체를 다시 쓰지 말고 **깎인 항목만 손본다.** 전문가가 글을 고칠 때
평균 8군데를 바꿨고, 바꾼 유형은 **진부한 표현 · 중복 · 맥락 없는 서술 ·
과하게 꾸민 문장 · 지나치게 매끄럽고 달콤한 톤** 이었다 (AI-Slop to AI-Polish).
이 다섯 가지를 먼저 본다.

**분량을 늘려 4번을 올리려 하지 않는다.** 5번과 6번이 함께 깎여 손해다.

**12점을 넘기면 6-2 로 넘어간다.** 넘지 못하면 5단계로 돌아가 깎인 항목만 고치고
다시 잰다. 최대 3회.

3회를 돌려도 12점에 못 미치면 **멈추고 사용자에게 보고한다.** 항목별 점수와
무엇이 부족한지 그대로 보여주고, 양식 보완이 필요한지 함께 판단한다.
억지로 통과시키지 않는다.


### 6-2. `글검수` — 사실 대조

`글검수` 에이전트를 부른다. 세밀하게 잡아내는 검사자 역할이다.

- `brief.md` · `research.md` 와 `post.md` 를 대조해 **근거 없는 문장**을 찾는다
- 수치를 대조한다 — **다만 기준이 글의 종류에 따라 다르다** (아래)
- 읽기만 한다. 클릭·입력·다운로드를 하지 않는다

#### 수치를 무엇과 맞출 것인가

EMS 는 **교육 기수**를 관리한다. 해커톤·박람회·발대식 같은 행사는 EMS 에 없다.
없다고 해서 지어낸 수치인 것은 아니므로, 글의 종류를 먼저 가른다.

| 글의 종류 | 수치 기준 | EMS 대조 |
|---|---|---|
| **교육 기수** — `AI 챔피언 그린 3회차` 처럼 EMS 에 기수가 있는 건 | **EMS 가 기준.** 기사 숫자가 달라도 EMS 를 쓴다 | 한다. ❌ 하나면 고치고 다시 검수 |
| **행사·소식** — 해커톤·박람회·발대식·수상 등 실제로 있었으나 우리 기수가 아닌 건 | **주최 기관 보도자료가 기준** | **건너뛴다** |

행사 글은 대신 이렇게 본다.

- 모든 수치에 **출처가 붙어 있는가.** `research.md` 의 보도자료·기사 중
  어느 것에서 왔는지 짚을 수 있어야 한다
- 출처를 짚지 못하는 숫자가 하나라도 있으면 **그 숫자를 뺀다.** 지어낸 것이다
- 본문에 출처를 밝힌다 — "행정안전부가 6월 17일 낸 보도자료에 실린 말입니다" 처럼
- **EMS 에 없다는 이유로 막지 않는다.** 실제로 있었던 행사라면 통과다

애매하면 EMS 교육과정 목록을 먼저 본다. 거기 기수가 있으면 교육 기수 글이고,
없으면 행사·소식 글이다.

### 6-3. 2차 — `발행검수`

`발행검수` 에이전트를 부른다. 최종 승인자 역할이다.

**1차 결과를 믿지 않는다.** 1차가 통과시킨 항목도 원자료와 다시 대조한다.
1차 보고서를 먼저 읽지 않게 되어 있으니, 부를 때도 1차 결과를 넘기지 않는다.

2차가 막으면 **발행하지 않는다.** 고쳐서 다시 돌린다.

두 검수 결과를 사용자에게 보여주고 확인받은 뒤 발행으로 넘어간다.

## 7. 네이버 블로그 발행
`post.md` 를 옮겨 `out/{slug}/naver.md` 를 만든다 — 앞머리에 `제목 / 카테고리: 교육 스케치 / 태그 / 대표사진`, 본문은 기사체(`~했다`)에 구분선 3섹션. 형식은 위 4단계의 네이버 규격을 따른다. 5-2 에서 보탠 내용이 있으면 그것까지 반영돼 있어야 한다.

그 다음 발행한다.
```
uv run prpub naver {slug}             # 발행 직전에서 멈춤 — 화면으로 확인
uv run prpub naver {slug} --publish   # 발행까지
```
- 기본은 **`--publish` 없이** 돌려 사용자에게 화면을 보여주고 확인받은 뒤, 다시 `--publish` 로 발행한다.
- 로그인 세션이 없다는 오류가 나면 `uv run prpub naver-login` 을 먼저 실행하고 사용자에게 로그인을 요청한다.
- 창이 뜨고 글이 채워지는 데 2~3분 걸린다. 중간에 끊지 않는다.

## 8. 사이트 반영
`config.toml` 의 `daeasy_repo` 를 확인한다.
- **비어 있으면**: 여기서 멈추고, `out/` 에 생성된 패키지 목록과 "daeasy 저장소 경로가 설정되지 않아 사이트 반영은 하지 않았다"를 보고한다. 아래 9단계도 하지 않는다.
- 설정돼 있으면: 저장소의 콘텐츠 규칙(`CLAUDE.md`, 기존 교육후기/인사이트 파일 구조)을 먼저 읽고, `meta.json.section` 에 맞는 위치에 게시글·이미지를 추가한다. 브랜치 `pr/YYYY-MM-DD` 를 만들어 커밋하고 push 한 뒤 PR 링크를 보고한다. main 에 직접 push 하지 않는다.

## 9. 정리
네이버 발행까지 끝난 건만 `uv run prpub done <폴더명...>` 으로 접수함에서 발행완료/ 로 옮긴다.
