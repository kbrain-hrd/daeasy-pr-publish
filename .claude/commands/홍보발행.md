---
description: 접수함의 홍보자료 양식을 검증하고 게시글을 작성해 daeasy 사이트에 일괄 발행한다
---

접수함에 쌓인 홍보자료를 한 번에 발행한다. 아래 순서를 **그대로** 따르고, 각 단계 결과를 짧게 보고한다.

## 1. 검사
`uv run prpub scan` 을 실행해 접수 건 목록과 검증 결과를 보여준다.
- ❌ 건은 오류 내용을 그대로 보여주고 **이번 발행에서 제외**한다. 등록자에게 전달할 수정 요청 문구를 한 줄로 만들어준다.
- 접수함이 비어 있으면 여기서 끝낸다.

## 2. 패키지 생성
`uv run prpub build <폴더명...>` 으로 통과한 건만 빌드한다. `out/{slug}/` 에 `brief.md`(등록 내용 정리), `meta.json`, `images/`, `files/` 가 생긴다.

## 3. 사진 · 관련 링크 (LLM 이 정한다)
- **사진**: `images/` 의 사진을 하나씩 **직접 열어 보고** (Read) 각 사진에 한 줄 캡션을 붙인다. 대표 사진은 교육 장면이 잘 드러나고 얼굴이 크게 나오지 않은 것으로 고른다. 결과를 `out/{slug}/photos.md` 에 `번호 · 파일 · 캡션 · 대표 여부` 로 기록한다.
- **관련 링크**: `교육 기관 + 교육과정 + 교육 일자` 로 WebSearch 해서 이 교육을 다룬 **기사·기관 공지·보도자료**를 찾는다. 실제로 열리는 페이지만 후보로 올리고(WebFetch 로 확인), 관련 없는 결과는 버린다. 후보가 없으면 "관련 링크 없음"으로 두고 만들어내지 않는다.

## 4. 게시글 작성
각 `brief.md` + `photos.md` 를 읽고 **게시글을 직접 쓴다** → `out/{slug}/post.md`:
- 형식: 맨 위 `# 제목`, 아래 본문. 제목 후보 3개를 본문 끝 `<!-- 제목 후보: … -->` 주석으로 남긴다.
- 문체 (기본): **교육후기체** — daeasy 사이트 `/cases` 에 올라가는 글의 문체다. 기준은 실제 게시글 `킨텍스에서 보낸 이틀, 2026 AI챔피언 해커톤 현장 이야기`.
  - 화자는 **"저희"(데이지)**, 종결은 존댓말 `~습니다`. 교육을 운영하고 온 사람이 현장에서 본 것을 전하는 톤이다. 보도자료의 `~했다/~이다`, 블로그의 `~했어요`를 쓰지 않는다.
  - 제목은 헤드라인이 아니라 **장면을 부르는 이름**이다. `<장소·기간>에서 보낸 <기간>, <무엇> 이야기` 또는 참가자의 말 한 줄을 앞세우는 구조. 수치를 제목에 나열하지 않는다.
  - 첫 문단은 `지난 <날짜>, 저희는 <장소>에 있었습니다` 로 시작해 언제·어디서·누가·무엇을 한 문단에 담는다.
  - **`## 소제목` 2~3개로 본문을 나눈다.** 사이트가 이 H2로 우측 목차를 만들기 때문에 없으면 목차가 비어 보인다. 소제목은 명사 나열(`교육 성과`, `참여자 반응`)이 아니라 **글의 한 대목을 가리키는 말**로 쓴다 (예: `"엑셀만 쓰다가 눈이 트였다"`, `샘플 데이터를 쓰지 않았습니다`). 길이는 10~25자.
  - 참가자·관계자의 말은 문단 안에 자연스럽게 녹이거나, 무게가 있으면 한 줄로 떼어 강조한다.
  - 숫자는 한 문단에 몰아 담되 성적표처럼 늘어놓지 않는다.
  - 마지막 문단은 **다음 교육으로의 초대**로 맺는다 (예: `다음 무대에 오를 분들을 데이지 AI챔피언 교육에서 기다리겠습니다.`). 사이트가 본문 뒤에 "교육 문의" CTA 를 자동으로 붙이므로 본문에 문의처를 적지 않는다.
  - 분량은 6~9문단(H2 포함).
- 사진 캡션은 `<장면 설명>. (사진 = <제공처>)` 형식으로 쓴다. 제공처를 모르면 괄호를 생략한다.
- **네이버 해시태그** — `naver.md` 앞머리의 `태그:` 에 12~16개를 아래 묶음대로 채운다. 검색으로 사람이 찾아올 말을 넣되, **교육에 실제로 있었던 것만** 쓴다. 다루지 않은 기술·유행어를 유입 목적으로 붙이지 않는다.
  | 묶음 | 넣을 것 | 출처 |
  |---|---|---|
  | 브랜드 (항상) | `데이지` `DAEASY` `케이브레인컴퍼니` `공공기관AI` | 고정 |
  | 기관 | 기관명, 통칭이 따로 있으면 함께 (`부산시` `부산시청`) | `meta.json` 교육 기관 |
  | 과정 | 과정명과 그 상위 이름 (`AI챔피언` `AI챔피언그린`) | 교육과정 |
  | 주제 | 실제로 다룬 도구·산출물 (`챗GPT활용` `민원데이터` `대시보드`) | 다룬 주제 · 실습 결과물 |
  | 대상 | 참여자를 부르는 말 (`공무원교육`) | 참여 인원·대상 |
  | 마무리 | `업무혁신` `디지털전환` 중 1~2개 | 고정 후보 |
  - 띄어쓰기 없이 붙여 쓰고, **앞머리 `태그:` 와 본문 맨 끝 `#태그` 양쪽에 모두 적는다.**
    - 앞머리 것은 발행 팝업의 "태그 편집"에 등록돼 **네이버 태그 검색에 걸린다.** 기존 글들은 이걸 안 해서 검색 노출을 받지 못했다.
    - 본문 끝 것은 이 원고를 **인스타그램·유튜브에 그대로 옮겨 쓸 때** 필요하다. 그쪽은 본문 해시태그가 유일한 수단이다.
- **네이버 글 맺음 블록**은 아래 5줄로 고정한다. 네이버 블로그 글 안에서 그 블로그 주소를 다시 적을 이유가 없으므로 블로그 줄은 넣지 않는다. URL 을 적으면 에디터가 링크 카드로 바꾸는데, 그 카드는 홈페이지 하나만 나오게 둔다.
  ```
  운영사: (주)케이브레인컴퍼니
  브랜드: 데이지(DAEASY)
  이메일: data-edu@kbrainc.com
  홈페이지: https://daeasy.vercel.app
  SNS: instagram.com/daeasy.official
  ```
- **강조 카드** — 글에서 가장 무게 있는 것 하나씩만 카드로 뽑는다. 사진을 대신하는 장식이 아니라 핵심을 세우는 장치다.
  - `::인용 <말>|<누가·언제>::` — 글 전체에서 **한 개만**. 제목이나 소제목으로 이미 쓴 말은 카드로 또 쓰지 않는다. 나머지 인용은 본문 문장 안에 둔다.
  - `::수치 <값> · <라벨>|<값> · <라벨>|…::` — 글 전체에서 **한 개만**, 항목은 3~4개. `meta.json` 의 참여 인원·인증 결과·만족도·결과물 수에서 가져오고, 없는 수치는 만들지 않는다.
  - 양식에 인용할 말이 없거나 내세울 수치가 없으면 그 카드는 쓰지 않는다. 두 카드 다 없어도 된다.
  - **사진이 한 장도 없는 건**도 카드로만 채운다. 대표 사진 자리는 비워 두고, 카드 개수는 늘리지 않는다 — 사진이 없다고 카드를 더 넣으면 글이 카드 목록처럼 보인다.
- 사용자가 "뉴스기사체"를 지정하면 그 톤으로: `~했다/~이다` 종결, 역피라미드(첫 문단에 누가·언제·어디서·무엇을·규모), 수치 우선, 제목은 `기관, 핵심 사실… 수치` 구조, 인용은 `참여자들은 "…"는 반응을 보였다` 형식, 마지막 문단은 데이지 공식 소개로 맺는다. `데이지 관계자는 …라고 밝혔다` 같은 **가짜 발언 귀속은 금지**.
- 구성: 첫 문단은 01 기본 정보(누가·언제·어디서·무엇을), 둘째 문단부터 02 교육 내용(특별했던 점·결과물), 수치, 03 참여자 반응 순. "강조할 점"이 있으면 그 메시지를 맺음 문단 직전에 담는다.
- **사실의 선**: 양식에 적힌 사건·장면·말만 사실로 쓴다. 없는 대화, 없는 장면("30분쯤 지나자 질문이 나왔다" 류), 없는 인물 묘사("십 년 넘게 엑셀 쓴 분")를 만들지 않는다. 대신 다음은 써도 된다 — (a) 과정이 일반적으로 다루는 내용의 설명("이 과정은 …을 순서대로 다룹니다"), (b) daeasy 공식 소개 문구(행안부 AI챔피언 운영기관, "실제 조직의 데이터와 문제를 가지고 풀어내는 프로젝트 기반 학습" 등 사이트에 있는 것), (c) 사실에서 바로 나오는 해석("도구가 바뀐 게 아니라 데이터를 보는 방식이 바뀐 것").
- "참가자가 한 말"이 있으면 **원문 그대로 인용**한다(따옴표 안 문장을 고치지 않는다). 없으면 반응 문단을 쓰지 않는다.
- 필수 항목만 채워진 건은 (a)(b)로 살을 붙여 최소 5문단을 만들되, 검사 경고("사실 나열 위주")를 사용자에게 같이 보여준다.
- 사진은 `photos.md` 캡션으로, 대표 사진을 첫 이미지로 배치한다. 관련 링크 후보는 본문 끝 "관련 링크" 항목으로 붙인다.
- 작성 후 **제목·첫 문단·인용문·관련 링크 후보**를 사용자에게 보여주고 확인받는다.

## 5. 사이트 반영
`config.toml` 의 `daeasy_repo` 를 확인한다.
- **비어 있으면**: 여기서 멈추고, `out/` 에 생성된 패키지 목록과 "daeasy 저장소 경로가 설정되지 않아 사이트 반영은 하지 않았다"를 보고한다. 아래 6단계도 하지 않는다.
- 설정돼 있으면: 저장소의 콘텐츠 규칙(`CLAUDE.md`, 기존 교육후기/인사이트 파일 구조)을 먼저 읽고, `meta.json.section` 에 맞는 위치에 게시글·이미지를 추가한다. 브랜치 `pr/YYYY-MM-DD` 를 만들어 커밋하고 push 한 뒤 PR 링크를 보고한다. main 에 직접 push 하지 않는다.

## 6. 정리
사이트 반영까지 끝난 건만 `uv run prpub done <폴더명...>` 으로 접수함에서 발행완료/ 로 옮긴다.
