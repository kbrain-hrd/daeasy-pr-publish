# daeasy 홍보자료 발행 도구 (초안)

다른 팀이 **한글/워드 양식 + 사진·자료 폴더**로 홍보자료를 접수함에 넣으면,
개발자가 클로드코드에서 `/홍보발행` 한 번으로 검증 → 게시글 패키지 생성 → 사이트 반영까지 처리합니다.

## 흐름

```
[각 팀]   templates/홍보자료_양식.hwp 를 채움
          접수함/2026-08-25_부산시_그린5회차/
          ├── 홍보자료_양식.hwp        ← 표만 채우면 됨 (docx·hwpx 도 됨)
          ├── 사진/  현장1.jpg …
          └── 자료/  결과보고서.pdf …

[개발자]  claude  →  /홍보발행
          1. 접수함 검사 (필수 누락·형식 오류 건 걸러냄)
          2. 통과분 → out/<slug>/brief.md(등록 내용 정리) + images/ + files/
          3. LLM 이 사진을 보고 캡션·대표 사진 결정, 웹검색으로 관련 링크 후보 수집
          4. LLM 이 post.md(제목+본문) 작성 → 담당자 확인
          5. daeasy 저장소에 게시글 추가 → 브랜치 커밋·push → PR
          6. 처리한 폴더를 발행완료/YYYY-MM/ 로 이동
```

## 설치 · 실행

```bash
uv sync
uv run prpub template          # templates/ 에 docx + hwp 양식 생성 (hwp 는 한글 설치 시)
uv run prpub scan              # 접수함 검증
uv run prpub build             # 패키지 생성
uv run prpub done <폴더명>     # 발행완료로 이동
uv run python scripts/make_fixtures.py   # 테스트용 접수 폴더 4개 생성
```

`config.toml` 에서 접수함 위치(공유드라이브 등)와 daeasy 저장소 경로를 설정합니다.

## 양식 항목 (12개)

글(제목·본문)은 `/홍보발행` 에서 LLM 이 작성합니다. 등록자는 사실과 어필 포인트만 기입합니다.
사진 캡션·대표 사진·관련 링크도 양식에서 받지 않고 `/홍보발행` 에서 LLM 이 사진을 보고, 웹을 검색해 정합니다.

| 구분 | 항목 |
|---|---|
| 01 기본 정보 | 교육명 · 교육기관 · 교육 일자 · 회차 · 참여 인원·대상 |
| 02 교육 내용 | 핵심내용 · 과정 내용 · 실습 결과물 · 이 과정의 주요 포인트 |
| 03 교육 만족도 | 교육 만족도 |
| 04 게시 방향 | 희망 헤드라인(선택) · 희망 해시태그(선택) |

검사 단계에서 비어 있으면 잡는 항목: 교육명 · 교육기관 · 교육 일자 · 참여 인원·대상 · 핵심내용.
양식에는 필수 표시를 하지 않고, `/홍보발행` 검사 결과로 등록자에게 알려줍니다.

**회차**는 장기·연속 과정일 때만 씁니다. 교육 일자 옆에 나란히 놓았습니다.

**게시 위치·게시 희망일·등록자는 받지 않습니다.** 우리가 정하는 것이라 물을 이유가 없습니다.
대신 희망 헤드라인·해시태그를 받습니다. 담당자가 "이 글로 뭘 말하고 싶은지" 한 번 생각해보게 하는 것이
목적이라 필수는 아닙니다. 비면 LLM 이 정합니다.

`prpub build` 결과의 `brief.md` 가 이 항목을 그대로 정리한 파일이고, LLM 은 이것만 보고 `post.md` 를 씁니다.

항목을 바꾸려면 `prpub/schema.py` 의 `FIELDS` 를 고치고 `uv run prpub template` 로 양식을 다시 뽑습니다.
**확인은 `templates/` 의 양식 파일을 직접 열어서 합니다.** 별도 미리보기 이미지는 두지 않습니다 —
항목을 바꿀 때마다 같이 갱신하지 않으면 옛 양식을 보게 되기 때문입니다.

## 게시글 그래픽

수치를 그림으로 넣을 때는 `scripts/make_chart.py` 를 씁니다. 단계별 인원을 주면
**형태를 알아서 고릅니다** — 그냥 막대로 늘어놓으면 값이 줄어드는 그림이 되어
성과가 손실처럼 읽히기 때문입니다.

```bash
uv run python scripts/make_chart.py --out docs/preview/img/green3.svg \
    --stages "선발=109,수료=98,인증=93" --title "인증률" --sub "271명이 지원해 경쟁률 2.7 : 1"
```

| 데이터 | 나오는 형태 |
|---|---|
| 달성률 70% 이상 | **미터** — 큰 숫자 + 채움 막대. "85% 달성"으로 읽힘 |
| 달성률 70% 미만 | **가로 막대** — 단계별 차이를 보여주는 게 맞음 |
| 단계가 둘 | **미터** — 막대 두 개는 그래프로 칠 것이 없음 |

**지원 인원은 넣지 않습니다.** 정원 제한으로 줄어든 것이라 성과와 성격이 다릅니다.
경쟁률은 부제로 적습니다. 두 조각짜리 파이·도넛은 쓰지 않습니다.

headline 숫자 여러 개는 그래프 대신 본문에 `::수치 109명 · 선발|98명 · 수료|93명 · 인증::`
로 적으면 사이트의 수치 카드로 그려집니다.

## 지원 형식

| 형식 | 파싱 | 비고 |
|---|---|---|
| `.hwpx` | XML 직접 파싱 | 어느 PC에서나 |
| `.docx` | python-docx | 어느 PC에서나 |
| `.hwp` | 한글 COM → hwpx 변환 후 파싱 | **한글이 설치된 PC에서만** |

## 아직 없는 것

- **daeasy 사이트 반영 단계** — 사이트 소스 저장소가 확보돼야 게시글 저장 방식에 맞춰 연결 가능. 그 전까지 `/홍보발행` 은 `out/` 생성까지만 하고 멈춤.
- 회차별 실적(신청·선발·수료·인증)은 K-Brain EMS 에 있습니다. 지금은 손으로 옮겨 적어야 합니다.
- 공유드라이브 접수함 경로 미정 (`config.toml` 의 `inbox`).
